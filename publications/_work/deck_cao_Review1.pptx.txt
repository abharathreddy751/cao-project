REVIEW 1  /  02
1. Problem Substantiation




1
Modern systems use different resources such as CPUs, GPUs, FPGAs and edge devices.



2
Each resource has different strengths for different workloads.



3
Resource availability can change while tasks are running.



4
Fixed scheduling may send a task to a busy or unsuitable resource.



5
The problem is to choose the best resource for each task at run time.

--- slide 3
REVIEW 1  /  03
2. Why This Problem Needs to Be Solved




1
Workloads can change in size and type during execution.



2
CPU, memory, queue length and network conditions can also change.



3
Unused resources may remain idle while another resource is overloaded.



4
Manual or fixed decisions cannot react to these changes.



5
Computer-based scheduling can make these decisions continuously.

REVIEW 1  /  06
5. Limitations and Gap Identified




1
The existing approach does not mainly predict the best resource using machine learning.



2
It uses resource-specific scheduling mechanisms rather than a lightweight ML resource-selection model.



3
Real-time resource conditions are not its main scheduling focus.



4
It is not specifically designed around distributed edge devices.



5
More adaptation is needed when workload and system conditions change.

--- slide 7
REVIEW 1  /  07
6. Proposed Solution




1
Monitor the current condition of each available resource.



2
Use task type, task size and system conditions as scheduling inputs.



3
Use a lightweight ML model to predict the suitable resource.



4
Offload the task to the selected device.



5
Use execution results as feedback for later scheduling decisions.

7. Main Functionalities




1

2
Build a task graph and check task dependencies.



3

4
Predict the suitable resource for each ready task.



5
Execute independent tasks in parallel and collect the results.
